# PR review follow-up, round 6 — 2026-10-26

v0.3.12 addresses four findings against `d49ebdb`, including the P1 duplicate-renderer-ID crash.

- **Type changes:** normalize repeated pathname blocks and raw `T` statuses before path-keyed maps or renderer items. A file↔symlink transition is one explicit collapsed unsupported entry, with combined change counts where available, not a partially overwritten two-way patch. The UI explains the limitation and disables unsupported preview/expansion; explicit patch requests return `409 unsupported_type_change`. Other files remain usable. Snapshot and metadata/paged paths share normalization.
- **Synthetic path quoting:** centralize Git C-style pathname quoting and untracked patch generation. Newlines, tabs, quotes, backslashes and mixed Unicode names are escaped in both snapshot and explicit-file output. Metadata IDs retain the real pathname. The pinned parser is used to verify round trips.
- **Oversized pages:** a failed bounded Git page is split sequentially and retried over smaller path sets. A single oversized path returns a bounded truncated placeholder. Each successful page assembly immediately discards patches over the ordinary per-file cap so recursive results cannot accumulate large raw patches; unrelated ordinary files keep their patches. Explicit full-file requests retain their existing larger cap, not an unlimited override.
- **Prototype-safe paths:** null-prototype dictionaries hold server patch payloads, snapshot page payloads, client records, seeded/kept record copies and per-path context. Reserved names such as `__proto__`, `constructor` and `toString` are ordinary own keys. Malformed single-file patch parsing is contained as a localized per-file error rather than throwing from a whole-view state update.

Real API regressions cover both type directions in snapshot/paged and all/staged/unstaged scopes, quoted special names through ordinary and full requests, reserved-key payload ownership, and a tracked 33-MiB single-line replacement alongside an ordinary file. The production regression mounts the built API/UI with actual Git repositories, first with a whole snapshot and then a forced/oversized paged view; it checks no duplicate IDs, supported ordinary content after placeholders, reserved-key context expansion and unchanged fixture state/index.

Playwright's object transport itself can lose an own `__proto__` field when deserializing structured results, so the regression transfers that diagnostic payload as JSON text and parses it explicitly rather than mistaking a test-transport limitation for a server failure.

All previous storage, tracking, PR, worker, sidebar and scroll regressions remain enabled. Final test totals, installed-runtime evidence and CI are recorded in the PR/local validation artifact. Draft remains, no merge or Store publication; no native platform or long-duration soak claim is added.

The finalized review also retained an aggregate-cap variant: 70 individually pageable files each replacing a 250,000-character line. Its regression checks initial/next/final pages, ≤1-MiB actual patch bytes and cursor advancement only over delivered files. The earlier draft type-change/quoting comments became unavailable before replies (their endpoints return 404), so those extra hardening fixes are recorded in the PR summary rather than claimed as successfully replied-to threads.
